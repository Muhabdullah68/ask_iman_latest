#### Firebase Init:

- Verify services: `FirebaseAuth.instance`, `FirebaseFirestore.instance`, `FirebaseStorage.instance` all resolve on web after hot restart
- Auth flows (sign in / sign up / pending approval) = identical to app, use same firestore `users/{uid}` document
- Rules: Firestore Security Rules already protect documents; those same rules apply to web (great!)

#### 🛡️ ADMIN DASHBOARD SECURITY ARCHITECTURE (CRITICAL):
```
RULE: Admin Dashboard = HIDDEN from website UI (no button, no nav link, no shortcut hint)
```

| Measure | Implementation |
|---|---|
| **1. No Nav Entry** | Admin button in Profile screen → `if (!kIsWeb && user.role == admin)` — visible in APP ONLY. On web it simply does not render. |
| **2. Hidden Deep Route Only** | Admin lives at URL `/secret-admin-dashboard` (not `/admin`). NOT in any bottom nav, app bar, settings list. URL is memorized by admin user (you). |
| **3. Client-Side Role Check** | Route guard middleware: if `!signedIn` → redirect to `/auth/signin`. If `signedIn && user.role != admin` → redirect to `/home` with silent snackbar "Not authorized". |
| **4. Server-Side Rules (double-protect)** | Firestore `.rules` for sensitive collections (approvals, donations ledger, users list) → `allow read, write: if request.auth.token.role == 'admin'` — this means even if someone GUESSES `/secret-admin-dashboard` URL, they CANNOT load any data without the Firebase auth token role claim. |
| **5. Custom Claim (Role)** | Admin role stored as a Firebase Auth Custom Claim (set via Firebase CLI or Functions). Never trust only a firestore field for role — use the token claim. |
| **6. No Indexing / SEO** | `Route.meta: { noIndex: true }` for admin route. `<meta name="robots" content="noindex, nofollow">` injected when route is active. Never appears in sitemap.xml |
| **7. Admin Confirmation To Use Website** | If Admin Dashboard → Admin must go to `/secret-admin-dashboard` directly (bookmark URL). No way for a regular user to stumble into it. There's zero UI breadcrumb, zero nav, zero mention. |

#### What Admin can do on web = exactly what Admin can do in app:
- 12 sub-tabs (Approvals, Pending Users, Classes, Charity, Donations, Causes, Requests, Family Groups, Classes, Users, Registrations, Enrollments, Teacher Apps)
- CRUD operations against firestore — same as app
- Data table with filters, pagination, sorting
- Export CSV
